## History numbered pages (20 November 2026, deployed as `c10a2a0f`)

The user asked for the History tab's "Load 100 more" button to become numbered pages (1, 2, 3, …), sized by the existing Rows per page setting, and to deploy once tested. **Implemented, tested and deployed** the same day; not committed to Git. Firmware, device protocol and migrations are unchanged.

- **Dashboard:** the table shows one page at a time. Below it: Previous/Next, page numbers (first, last and the pages around the current one, with … gaps; 7 slots, 5 on phones) and a "Page [n] of N" box. A typed number past the end opens the last page.
- **Paging rules:** every page of a view reads one pinned window: the applied range, or for Latest the window its first response reported. Pages therefore do not shift while new readings arrive; choosing Latest again refreshes. The page count comes from the existing selection count, and for Latest from a count of its pinned window. Changing size, order, view or device returns to page 1.
- **No. column:** it now counts across all pages (1 = oldest reading of the view). With newest first it stays blank until the count arrives. Without a count, the pager steps page by page.
- **Backend:** optional `offset` on entry-paged `/api/history` (`src/history-pages.js`, documented in API.md). Neighbouring pages still follow cursors. A jump uses a seek: block sizes pick a pivot, one exact count follows, and only a short remainder goes through SQL `OFFSET`. A deep jump costs about one selection count (synthetic 31 days: ≤0.19 s at 5-second sampling). It relies on the existing rule that each reading lies within 60 s after its block start.
- **Evidence:** 144/144 tests, 20/20 synthetic browser checks plus failure paths, and a read-only production D1 comparison (5 pages equal a plain sort). Details are in VERIFICATION.md.

## Discord gas-warning alert (13 November 2026, deployed)

User asked for a Discord message when a gas warning has lasted one hour, and authorized creating the bot, setting the Worker secret and deploying. **Implemented:** `cloud/coop-monitor-worker/src/gas-alerts.js`, run by a new `*/5 * * * *` cron (the `*/15` cron still runs maintenance only). For each device it reads the last ~80 minutes of D1 readings. It posts once per episode when the firmware `GAS_WARNING` flag has been continuous for `GAS_ALERT_AFTER_MINUTES` (60). A non-warning reading or a gap of more than 10 minutes breaks continuity. If the newest reading is over 10 minutes old the device is treated as offline and nothing is sent or cleared. A single "no longer continuous" message follows when a notified episode ends. D1 is written only when a message is sent (`system_state` key `gas_alert:<deviceId>`). Failed sends are retried on the next run. The alert works off the firmware's own warning (MQ-135 relative response); messages say it is not calibrated ammonia ppm. The device exchange path is unchanged.

- **Discord:** private application/bot "Coop Monitor" (application ID `1570626231106543746`) in the user's developer account; public install link set to None, Public Bot off. Invite: `https://discord.com/oauth2/authorize?client_id=1570626231106543746&scope=bot&permissions=3072` (View Channels + Send Messages). ## Invariants for future work

- Preserve `coopcal` calibration format/namespace, other NVS formats, partitions, TLS verification, warning guards, immutable retry IDs/payloads, acknowledgement semantics and desired/applied configuration separation.
- Ten-minute boot warm-up. Calibration is ten-minute stabilization plus five-minute collection, at least 60 valid samples. Automatic threshold: `max(baseline * 1.15, baseline + 3 * SD)`; manual: 10–2399 mV **at the divided ADC input**. Warm-up, calibration, missing/invalid calibration, invalid AHT readings and ADC-high guard suppress gas warnings. Confirmation defaults to three samples.
- RAM holds 64 readings/16 logs; overflow can drop oldest entries and reboot loses pending data. Firmware 1.1.0 and later also keep a microSD backup (`sd_backup.h`): a 4 KiB RAM buffer appended to a new `/coop/bNNNNN.csv` each boot, as whole 512-byte sectors every 15 minutes or at 3 KiB, each write read back and compared. A power cut loses at most about three minutes still in RAM. Nothing backfills the SD copy to the cloud. No persistent flash measurement queue. At default sampling, 64 readings represent about 128 seconds before overflow, not guaranteed outage recovery.
- Commands are allowlisted with durable receipts and explicit uncertain recovery. No arbitrary shell, OTA, remote provisioning or remote calibration import. Cloud Console is bounded firmware events/results, not every USB/boot-ROM line.
- Keep the exact workers.dev exchange endpoint available: firmware validates it and follows no redirects. A replacement dashboard domain alone does not migrate device traffic.
