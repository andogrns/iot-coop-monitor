## Implemented fixes

| Finding | Change | Evidence and remaining limits |
|---|---|---|
| Potential disclosure through unexpected error messages | `src/app.js` logs fixed event names instead of provider exception messages; handles even non-Error thrown values. `src/archive.js` stores a fixed failure code instead of raw provider text. Scheduled failures remain rejected with a sanitized error so failure reporting still works. | Injected private-looking exception text never appears in responses, maintenance reports or captured application logs. This is application logging protection, not a review of Cloudflare's account-level logs. |
| Secret redaction missed authentication schemes and multiword/quoted values | `src/protocol.js` now redacts Bearer/Basic values and JSON-style, quoted and multiword password/token/secret/SSID fields. | Tests cover these formats, the existing 64-hex-token rule and 512-character bound. Unknown/unlabelled formats are not guaranteed secret detection. Conservative redaction can remove diagnostic words after an unquoted secret until the next delimiter. IDs/acknowledgements are unchanged. |
| Login attempts could be reset by filling the IP map | New `src/login-throttle.js` removes only expired records. Active IP limits survive churn; the map stays at 1,000 entries. | Deterministic expiry/churn tests pass. When all slots are active, new IPs receive 429 until a slot expires. This trades short-lived local availability for bounded memory and intact limits. It remains **per-isolate**, not distributed abuse protection. |

## Report first: firmware-sensitive findings left unchanged

These were reported during the audit. No changes to ingestion identity rules, command delivery, pause logic, clock anchoring, retention timing or firmware were made to address them.

| Priority | Finding and evidence | Why a separate decision is needed |
|---|---|---|
| High — data integrity | **Deduplication is only within a minute window.** `exchange()` selects a block by uptime, then `mergeSamples()` compares sequence IDs only inside that block. Local reproduction stores two samples for the same device/boot/sequence when its uptime changes across a minute boundary. It requires an authenticated erroneous or malicious producer; the normal stable firmware retry passes. | A boot-wide identity index/check may add significant D1 writes and change how a conflicting retry is rejected. Choose a strategy and test RAM retirement/recovery before enforcing it. |
| Medium — command delivery | **The command queue count and insertion are separate operations.** Starting with nine queued commands, two simultaneous owner submissions both succeeded and left **11** active commands; exchange delivers at most ten at once. The log quota also uses a separate count followed by insertion, so simultaneous device exchanges can race its 60/hour budget (source finding, not separately load-tested). | Atomic admission needs regression coverage for firmware receipt/retry handling. Existing queued, accepted and running commands must not be discarded or reordered blindly. |
| Medium — capacity/pause behavior | **Usage estimates omit traffic and warning coverage.** A paused exchange adds **0** to the request estimate. Invalid/authentication-failed exchanges, some result-only writes and actual owner traffic are not metered by the minute counters; maintenance adds a fixed reserve. Request-budget exhaustion can return `paused: true` with `warning: false`; locally reproduced using 74,000 upload requests and the configured 21,600 reserve. Counters are attributed by sample-window day and refreshed every 15 minutes, not by every request's receipt time. | More accurate accounting, request warning thresholds and additional limits can change when ESP uploads pause and how much RAM data is discarded. Preserve the user-approved “warn, then pause” policy and two-second cadence when designing the change. |
| Medium — archive/retry boundary | **Archival eligibility checks block start, while ingestion eligibility checks individual sample time.** A minute beginning before the retention cutoff can contain samples still inside it. During that boundary interval, a retry can recreate a block already archived; a concurrent block change can also leave an archived older version and a retained newer version. Revision guards protect against deleting changed source, but do not make final reconstruction duplicate-free. | Review a full-window cutoff/safety margin and reconstruction deduplication before changing retention behavior. This is a source-derived race; ordinary archive/readback and changed-revision retention were tested, not a full real-time retention-boundary race. |
| Medium — command recovery/load | **Accepted/running commands have no bounded recovery age; terminal history is retained indefinitely.** These active states can occupy the queue until resolved. Pending-command scans have a device/created-time index, not an active-status index, and can scan growing history on every exchange. | Automatically expiring/deleting accepted or running receipts can interfere with restart/calibration execution and NVS recovery. Separate history indexing from a reviewed lifecycle policy; do not delete receipt history as a quick cleanup. |
| Medium — long-running/offline device | **The five-minute boot-clock drift rejection is permanent for the same boot ID.** After enough anchor drift or a delayed first exchange, otherwise valid payloads can receive `boot_clock_mismatch`. The current firmware retains IDs and retries failed exchanges; it does not negotiate an anchor correction. | Changing the anchor affects estimated study timestamps; changing boot identity affects idempotency. Requires coordinated firmware/backend design and physical testing. This was source inspection, not a measured problem on the live ESP32. |

## Other residual concerns and operational limits

- **Distributed abuse protection is not established.** The local login throttle cannot coordinate Worker isolates. `/health` performs an anonymous D1 query, and a syntactically valid unknown device credential/ID can cause a device lookup. There is no application-wide request guard for these paths. Cloudflare edge/account protections were not inspected. A narrowly scoped owner/health edge rule could help; a blanket `/api/*` bot challenge could disconnect the ESP32 and must not be deployed without review.
- **Archive capacity counts verified manifests, not every R2 object.** Interrupted jobs can leave uncatalogued objects. Orphans are not downloadable through the authenticated manifest endpoint, but their bytes are omitted from the application's estimate. Inventory and reconciliation need account authorization; do not delete unmatched objects automatically.
- **Archive throughput has a scale limit.** Thirty blocks per 15-minute cron means at most 2,880 blocks/day across all devices, before failures/hour boundaries reduce throughput. One continuously sampled device creates about 1,440 minute blocks/day. Two leave no idealized catch-up margin; three exceed it. Retention remains 30 days and the cron remains unchanged. More archival work also increases CPU, subrequests and storage operations.
- **Other maintenance costs grow with history.** Archive byte totals are summed during archival and capacity refresh; command expiry has no row limit; pruning by global log time lacks a leading global-time index. Boot cleanup compares ISO `T` timestamps with SQLite space-separated timestamps, which can delay removal within the cutoff date. These are bounded-study/scaling concerns; changing indexes adds write/storage costs, and cleanup of boot/command history requires the integration review above.
- **Login and session policy remains deliberately simple.** Owner access is one shared key; rotating it alone does not revoke existing cookies. Rotate the session secret as well if revocation is required. No credential rotation was performed.
- **No dependency/advisory or historical-secret certification.** Reviewed package metadata; no runtime npm dependencies are declared. The installed Wrangler toolchain was used to bundle/test, not upgraded or certified vulnerability-free. Known provisioning/secret paths are ignored; the matching tracked credential filename was a preparation script, not a credential data file. Secret contents and Git history were not scanned.
